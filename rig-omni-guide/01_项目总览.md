# 01 · 项目总览

## 一句话介绍

**RIG-Omni** 是一套跑在 ESP32-S3 芯片上的机器人固件。它的牛逼之处在于：**同一套源代码**，编译时选一下，就能变成四足机器狗、平衡小车、机械臂或者行走机器人。

## 这项目能干嘛？

想象一下你面前有个小机器人，圆屏当脸，会说话会做动作：

- 🗣️ **语音交互**：说"你好"它就被唤醒，和你聊天。语音识别靠云端，唤醒词在本地（离线、不占网）
- 🎭 **表情动画**：圆屏上显示 EAF 格式的动画表情（开心、生气、疑惑、撒娇……），说话的时候表情会跟着变
- 🐕 **机器狗形态**：四条腿会走，会坐，会摇尾巴，能做二十多种预设动作（打招呼、撒娇、游泳、打滚……）
- 🚗 **Hover 形态**：两个轮子会自己保持平衡，能切换成云台模式固定在桌上当摄像头
- 🦾 **ARM 形态**：五自由度机械臂，支持标定和示教（手把手教一遍，它自己复现）
- 📷 **摄像头**：有的硬件带摄像头，AI 可以"看"到东西然后告诉你那是什么
- 🔧 **远程工具（MCP）**：电脑上的 AI Agent 可以直接"调用"机器人能力，比如"让小狗向前走 5 厘米，然后摇个尾巴"——整个过程就是一次 MCP `tools/call`

## 四种形态，共享一套代码

这项目最巧妙的设计之一是"同一代码库 + Kconfig 编译时选择"：

```
main/
├── boards/
│   ├── common/          # 所有形态共用的驱动：IMU、按键、BLE、摄像头、电机协议
│   ├── puppy/           # 机器狗专属：robot.cc、robot_action.cc、motor.cc、表情资源
│   ├── hover/           # Hover 专属：同上 + IMU 平衡控制 + 云台模式
│   ├── arm/             # 机械臂专属
│   └── tars/            # TARS 专属：320×240 横屏终端界面
├── audio/               # 共用的音频处理链路
├── display/             # 共用的显示驱动 + LVGL
├── protocols/           # 共用的 MQTT/WebSocket
├── application.cc/h     # 共用的应用生命周期
└── mcp_server.cc/h      # 共用的 MCP 服务器框架
```

编译时 `idf.py menuconfig` 里选 Board Type = Puppy/Hover/Arm/Tars，编译器就只编对应的目录进去。

## 核心技术栈

| 层 | 技术 |
|----|------|
| 芯片 | ESP32-S3（双核 Xtensa LX7，240MHz，16MB Flash + 8MB PSRAM） |
| 框架 | ESP-IDF 5.5.x |
| 语言 | C++17（freertos + std::variant + lambda） |
| 构建 | CMake + Python 工具脚本 |
| 通信 | WebSocket / MQTT + BluFi 蓝牙配网 |
| AI | 本地离线唤醒词（ESP-SR AFE）+ 云端 ASR/TTS |
| MCP | 自建 JSON-RPC 2.0 服务端（参考官方 2024-11-05 规范） |
| 显示 | GC9A01 圆屏 240×240 / ST7789V2 横屏 320×240 + EAF 动画 |
| IMU | QMI8658C 六轴（I2C） |
| 电机 | EM3 总线舵机（Puppy/Hover）、SCS009（ARM/TARS）、KP4012 轮毂电机（Hover） |
| OTA | ESP-IDF 原生 OTA + HMAC 设备激活 |

## 这个项目为什么值得关注？

### 1. 把 MCP 落地到了嵌入式

MCP（Model Context Protocol）本来是让 AI Agent 和本地工具、资源通信的协议。这项目做了一件很酷的事：**把机器人的运动能力、摄像头、音量调节、电源控制……全部注册成 MCP tools**。AI Agent 只要会 MCP，就能直接操控机器人，不需要再写一套"机器人专用协议"。

### 2. 同一固件，四种硬件

很多机器人项目做死了——改一种形态就得改好多代码。RIG-Omni 用 "板级抽象层" 把差异隔离开了：每个形态实现自己的 Board 类，共用的框架代码一行不用改。

### 3. 音频链路很完整

从 I2S 硬件驱动 → Opus 编解码 → VAD 语音活动检测 → AEC 回声消除 → AGC 自动增益 → 唤醒词检测 → 云端 ASR/TTS，整条链路在代码里都能找到。

### 4. 运动控制不简单

Hover 形态是双轮平衡小车，靠 QMI8658C IMU 读姿态，闭环控制两个轮毂电机保持平衡。Puppy 形态是 5 舵机四足，有步态规划和动作序列执行。

### 5. 开源、可玩、硬件不贵

ESP32-S3 开发板几十块，整个机器人料成本大概几百块。固件开源 Apache 2.0，改一改就能做出自己的宠物机器人。

## 局限性（知道一下比较好）

- 语音交互依赖**云端服务**（ASR/TTS 要连外网），本地只有唤醒词是离线的
- MCP 服务器只实现了客户端发的 `initialize`、`tools/list`、`tools/call`，没有实现服务端主动推送 notification
- 部分板型的标定流程需要按键配合，不是全自动
- 不同硬件版本的引脚定义可能有差异，要对照自己的板子调整
