# 04 · 运动控制体系

## 四种形态的运动方式对比

| 形态 | 执行器 | 运动方式 | 核心文件 |
|------|--------|---------|---------|
| **Puppy** | 5 × EM3 总线舵机 | 四足步态 + 头部动作 | `robot.cc` + `robot_action.cc` + `motor.cc` |
| **Hover** | 2 × KP4012 轮毂电机 + 1 × EM3（头部） | IMU 平衡闭环 + 云台模式 | 同左 + `imu.cc` |
| **ARM** | 5 × SCS009 总线舵机 | 机械臂运动学标定 + 示教模式 | `ik.cc`（逆运动学） |
| **TARS** | 3 × SCS009 | 行走 + 转向 | `robot.cc` |

## IMU：所有运动的"感知之眼"

### 硬件

QMI8658C — 六轴 IMU，I2C 接口。集成了加速度计（3 轴）和陀螺仪（3 轴）。

### 读什么数据

```cpp
// imu.h 里暴露的全局变量
extern float roll;        // 翻滚角（度）—— Hover 平衡控制的核心
extern float pitch;       // 俯仰角（度）
extern float yaw;         // 偏航角（度）—— Hover 原地旋转用
extern float accel_x, accel_y, accel_z;  // 加速度（m/s²）
extern float pit_gyro;    // 俯仰角速度（°/s）
extern float dq;          // 积分增量
```

### Hover 怎么用 IMU 保持平衡？

Hover 是双轮小车——两个轮子，一个头部舵机。如果没有 IMU，它就是两个轮子而已，站不住。

平衡原理（极简版）：

```
1. IMU 高频读取 roll（翻滚角，车身左/右倾）
2. 目标 roll = 0（想保持竖直）
3. 误差 = 当前 roll - 目标 roll
4. 根据误差算出两个轮子的差速（PID 控制）
5. 输出到 KP4012 轮毂电机 —— 左轮加速、右轮减速，让车身往回倒
6. 同时如果被命令前进，整体加减相同速度
```

代码里三个控制模式：

| control_mode | 含义 | 控制逻辑 |
|--------------|------|---------|
| 0（小车模式） | 平衡 + 运动 | roll 闭环 + 差速驱动 |
| 1（云台模式） | 静止支撑 | 云台保持俯仰角（由 MCP `self.robot.pitch` 设定） |
| 2 | 标定模式 | 所有舵机断电，手动调零点 |

### Puppy 怎么用 IMU？

Puppy 虽然是四足，重心低、天然稳，但 IMU 仍然会读取姿态。`GetDeviceStatusJson()` 里把 IMU 数据塞进 JSON 返回，让 MCP 工具 `self.get_device_status` 能告诉你当前机器人有没有歪。

## 舵机驱动系统

### 三种电机协议

项目支持三种电机驱动，都在 `main/boards/common/motors/`：

| 电机 | 协议 | 用到的板型 | 特点 |
|------|------|-----------|------|
| **EM3** | 总线协议（类 Dynamixel） | Puppy、Hover 头部 | 支持读电压、角度反馈 |
| **SCS009** | 类 Dynamixel 总线协议 | ARM、TARS | 机械臂/行走机器人 |
| **KP4012** | 独立协议 | Hover 轮子 | 轮毂电机，支持差速驱动 |

EM3 和 SCS009 共用 `scs_bus.cc` 总线实现，因为协议几乎一样（ID + 指令 + CRC）。

### 总线通信架构

所有舵机挂在**同一个 UART 上**（UART2，波特率 1000000）：

```
ESP32-S3 ── UART2 ──▶ SCS009 #1 (ID=1)
                  ├──▶ SCS009 #2 (ID=2)
                  ├──▶ SCS009 #3 (ID=3)
                  ├──▶ SCS009 #4 (ID=4)
                  └──▶ SCS009 #5 (ID=5)
```

一条总线上多个舵机靠 ID 区分。ESP32 发指令（"ID=3 转到 1500us"），对应舵机响应。

### 舵机位置单位

舵机的"角度"其实用的是**脉宽微秒值**：

| 微秒 | 对应位置 |
|------|---------|
| 500us | 一端极限 |
| 1500us | 中间 |
| 2500us | 另一端极限 |

`robot_action.cc` 里的 `SetMotorAngle()` 接收 5 个舵机的微秒值，一次性发到总线。

## 四足机器人（Puppy）运动控制

### 三个并行的任务

```cpp
// 在 PuppyBoard 构造函数里创建

// 任务 1：机器人运动控制（10ms 周期）
xTaskCreatePinnedToCore([](void* arg) {
    while (true) {
        robot_control();
        vTaskDelay(pdMS_TO_TICKS(ROBOT_TASK_INTERVAL_MS));  // 10ms
    }
}, "robot_task", 4096, this, 5, &robot_task_handle_, 0);

// 任务 2：舵机总线 + IMU 读取
xTaskCreatePinnedToCore([](void* arg) {
    while (true) {
        motor_rx();            // 读舵机响应（电压反馈等）
        imu_read_once();       // 读一次 IMU
        vTaskDelay(pdMS_TO_TICKS(MOTOR_RX_TASK_INTERVAL_MS));
    }
}, "motor_rx_task", 4096, this, 5, &motor_rx_task_handle_, 1);
```

### 步态与动作

Puppy 有两种运动模式：

1. **速度模式**（`control_mode = 0`）：设定 vx（前后速度）和 vyaw（转向速度），`robot_control()` 循环在后台持续输出步态角度
2. **角度模式**（`control_mode = 1`）：直接设定 5 个舵机的目标角度，一次性执行

MCP 工具就是在改这两个模式的参数：

```cpp
// self.dog.move 用速度模式
SetDogSpeed(dog_vx, dog_vyaw, time);   // vx=±2.2*dog_vx, vyaw=∓2.8*dog_vyaw

// self.dog.set_motor_angle 用角度模式
SetAngle(a1, a2, a3, a4, a5, t);       // 5 个角度 + 延时
```

### 预设动作序列

Puppy 有 20+ 个预设动作（Wave、Swing、Sit 等），每个都是一串舵机角度序列。MCP 工具只是设置 `Action_ID`：

```cpp
mcp_server.AddTool("self.dog.Wave", ..., [this](...) {
    Action_ID = Wave_ID;       // robot_control() 循环看到这个值就切换动作序列
    vTaskDelay(pdMS_TO_TICKS(1000));
    return true;
});
```

动作之间有 1 秒延时，避免连续调用时动作打架。

## Hover 平衡小车控制

### 三个并行任务

Hover 因为需要更高频的平衡闭环，任务分得更细：

```cpp
// 任务 1：平衡控制主循环
xTaskCreatePinnedToCore([](void* arg) {
    while (true) { robot_control(); }   // 无延时，最高优先级
}, "robot_task", 4096, this, 12, &robot_task_handle_, 0);

// 任务 2：舵机总线读取（3ms 周期）
xTaskCreatePinnedToCore([](void* arg) {
    while (true) {
        motor_rx();
        vTaskDelay(pdMS_TO_TICKS(3));
    }
}, "motor_rx_task", 4096, this, 12, &motor_rx_task_handle_, 1);

// 任务 3：IMU 读取（2ms 周期 —— 非常快）
xTaskCreatePinnedToCore([](void* arg) {
    while (true) {
        imu_read_once();
        vTaskDelay(pdMS_TO_TICKS(2));
    }
}, "imu_task", 4096, this, 12, &imu_task_handle_, 1);
```

注意优先级是 12（比 Puppy 的 5 高很多），因为平衡控制必须实时。

### 云台模式

切换到云台模式（`control_mode = 1`）后：
- 两个轮子锁死（不执行平衡控制）
- 头部舵机跟随 `gimbal_pitch_target` 保持设定俯仰角
- 可以放在桌面上当稳定摄像头/屏幕

## 电池电量检测

两种方式共用的电量估算：

```cpp
// 2S 锂电池
// 6.6V = 0%
// 8.4V = 100%
if (voltage >= 8.4f) level = 100;
else if (voltage <= 6.6f) level = 0;
else level = (int)((voltage - 6.6f) / (8.4f - 6.6f) * 100.0f);
```

电压从**舵机的 PRESENT_VOLTAGE 寄存器**读取（不用专门的 ADC 电池检测电路）。每隔 60 秒自动读一次，也可以主动触发。

## 标定（Calibration）

标定就是"让舵机知道自己的零位在哪里"。如果舵机没标过，动作会歪。

### Puppy 标定流程

1. MCP 工具 `self.dog.calibrate(mode=1)` 或硬件三连击按键 → 进入标定模式
2. 所有舵机转到中间位置（1500us），然后断电（`EnableAllMotor(0)`）→ 手动摆正
3. 退出标定（`self.dog.calibrate(mode=0)`）→ `WriteZeroPos()` 把零位写入 NVS Flash
4. 下次上电自动从 NVS 读回零位

### ARM 标定 + 示教

ARM 机械臂额外支持**示教模式**——手把手把机械臂摆成一个动作序列，固件记录每个舵机的轨迹，然后可以回放。
